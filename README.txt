Сборка
------
1. Распакуй архив.
2. На Windows установи MSBuild (из Visual Studio или Visual Studio Build Tools)
   и .NET Framework 4.8 Developer Pack, если они отсутствуют.
3. Запусти publish.bat. Успешная сборка помещает один FileSigner321.exe
   в папку publish рядом с батником.
   Окно остаётся открытым после сборки. Подробности и ошибки сохраняются
   в publish.log. Для запуска из автоматизации используй publish.bat /nopause.
4. Для переноса на другой ПК скопируй только EXE. Для запуска нужен
   .NET Framework 4.8 или совместимое обновление .NET Framework 4.x.
   Visual Studio, PowerShell и установщик для запуска не требуются.

Работа
------
Выбери сертификат из хранилища Windows. Добавь или перетащи несколько
файлов и нажми «Подписать копии». Копии сохраняются рядом с исходным
файлом: имя-signed.ext, имя-signed-2.ext и т. д. Оригинал сохраняется.
Двойной щелчок по обработанному файлу показывает его копию в Проводнике.
Язык интерфейса меняется кнопками RU и EN внизу окна.

Authenticode: PS1, PSM1, PSD1, EXE, DLL, MSI, CAB и CAT. Windows должна
поддерживать формат файла. Для RDP используется системный rdpsign.exe.
Подпись выполняется без сервера отметок времени.

Новый сертификат создаётся в CurrentUser\My как самоподписанный Code
Signing с закрытым ключом пользователя. Срок задаётся в днях; по
умолчанию 10 календарных лет. «Экспорт .cer» сохраняет только публичную
часть. «Резервная копия .pfx» сохраняет сертификат и закрытый ключ
в файл, защищённый паролем. На другом ПК импортируй .pfx в «Личное»
хранилище пользователя. Пароль хранится отдельно от копии.
Новые ключи создаются экспортируемыми. Для уже существующих
неэкспортируемых ключей Windows не разрешает создать .pfx.
Доверие к сертификату на этом и других ПК настраивается отдельно.

Сведения «321.su» встроены в свойства EXE и окно «О программе».
Собранный EXE можно подписать своим сертификатом отдельно.
